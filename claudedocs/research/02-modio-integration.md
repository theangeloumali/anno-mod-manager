# 02: mod.io integration spec for the Anno mod manager

Researched 2026-11-19. Scope: a free, public Tauri 2 + React desktop mod manager for Anno 117: Pax Romana and Anno 1800 that talks to mod.io.

**Sources.** The source of truth is the official REST API reference at docs.mod.io. Where the rendered site returned 403 or rendered client-side, I read the same pages from mod.io's own docs repository, `github.com/modio/modio-docs` (`public/en-us/restapi/docs/*.api.mdx` and `public/en-us/game-integration/restapi/getting-started/*.md`, `main` branch, fetched 2026-11-19). Each endpoint table below was decoded from the OpenAPI blob embedded in those pages, so the METHOD, path and security scheme are mod.io's own. I made no write calls and created no account. The only live requests were three unauthenticated probes, noted where they are used.

**Notation.** `KEY` means a read-only `api_key` query parameter. `BEARER(read)` and `BEARER(write)` mean an OAuth 2.0 access token in `Authorization: Bearer` with that scope. `KEY | BEARER(read)` means either one works. Source: [docs.mod.io/restapi/introduction](https://docs.mod.io/restapi/introduction).

---

## TL;DR: the four facts that shape the build

1. **Login is the hard part, not browsing.** The email-code flow (`POST /oauth/emailrequest`, `POST /oauth/emailexchange`) requires **the game's** api_key, and a user-linked key is refused with `403 / 11017 error_auth_failed_limited_key_abilities` ([request-email-security-code](https://docs.mod.io/restapi/docs/request-email-security-code), [exchange-email-security-code](https://docs.mod.io/restapi/docs/exchange-email-security-code)). The game's key belongs to Ubisoft. A third-party tool can only get a user key ([introduction](https://docs.mod.io/restapi/introduction)). The login paths a third party can actually use are in §2.
2. **A shipped user key would be rate-limited for the whole user base.** User-linked API keys get **60 requests/minute**, OAuth user tokens 120/min, and game-linked keys are unlimited ([rate-limiting](https://docs.mod.io/restapi/rate-limiting)). One key embedded in a public app would be shared by every install.
3. **`api.mod.io` is dead; use `g-{game_id}.modapi.io` / `u-{user_id}.modapi.io`.** A live probe of `https://api.mod.io/v1/games/11358` returned `404, error_ref 14000: "Using api.mod.io is deprecated. Please use the modapi.io domain from your games dashboard"`. The documented paths are in [introduction](https://docs.mod.io/restapi/introduction).
4. **Ubisoft can switch third-party access off.** The Game Object has `api_access_options`, where bit `1 = OPEN` means "Allow 3rd parties to access this games API endpoints". Bit `2 = DOWNLOADS` off makes every `binary_url` carry an expiring verification hash. Bit `4 = AUTHORISED_DOWNLOADS` requires a bearer token to download ([get-game](https://docs.mod.io/restapi/docs/get-game), [schemas/game-object](https://docs.mod.io/restapi/docs/schemas/game-object)). The Anno values are unknown until someone calls `GET /games/{id}` with a key.

```ascii
                       +---------------------------+
                       |  Tauri 2 shell (Rust)     |
  React UI  <--IPC-->  |  modio client (reqwest)   |---- HTTPS ----> g-11358.modapi.io/v1  (Anno 117)
                       |  token in OS keychain     |---- HTTPS ----> g-4169.modapi.io/v1   (Anno 1800)
                       |  download + md5 verify    |---- HTTPS ----> mod.io CDN (binary_url)
                       |  installer -> mods folder |
                       +-------------+-------------+
                                     |
              writes ONLY to <Documents>/Anno 1800/mods  or  <Documents>/Anno 117 .../mods
              never to C:\Users\Public\mod.io\<game_id>\  (the in-game mod.io SDK's folder)
```

- **name_id.** The slugs `anno-117-pax-romana` and `anno-1800` come from the public URLs. Use the numeric ids. Mods can be looked up by slug with the `name_id` filter on `GET /games/{game-id}/mods` ([get-mods](https://docs.mod.io/restapi/docs/get-mods)).
- **Tag taxonomy: NOT retrieved.** Both mod.io pages render client-side, and the tag list is only available from `GET /games/{game-id}/tags` (`KEY | BEARER(read)`, returns Game Tag Option Objects, with an optional `show_hidden_tags`) ([get-game-tag-options](https://docs.mod.io/restapi/docs/get-game-tag-options)). That call needs an API key, and the brief forbids creating an account. **Do not hard-code categories.** Fetch them at runtime and cache them per game. Filter with `tags=` (must match all), `tags-in=` (any) and `tags-not-in=` ([get-mods](https://docs.mod.io/restapi/docs/get-mods)).
- **Game-version gating.** Anno 117's mod loader only loads mods whose `modinfo.json` has `"Anno": 8` ([anno-mod-loader: Changes with Anno 117](https://jakobharder.github.io/anno-mod-loader/changes-117)). Whether mod.io carries an equivalent game-version tag is unknown until the tags call above is made.

### Token lifetime and expiry

- Email-flow tokens default to **one year** (`date_expires` max = now + 31536000 s) ([exchange-email-security-code](https://docs.mod.io/restapi/docs/exchange-email-security-code), [schemas/access-token-object](https://docs.mod.io/restapi/docs/schemas/access-token-object)). Platform and OpenID flows cap at **one week** (now + 604800 s) ([authenticate-via-steam](https://docs.mod.io/restapi/docs/authenticate-via-steam)).
- The Access Token Object has `access_token`, `date_expires`, and a `refresh_token` that is returned "only by login flows that support it" ([schemas/access-token-object](https://docs.mod.io/restapi/docs/schemas/access-token-object)).
- Tokens can be revoked by the user or a mod.io admin, so apps must handle `401` ([introduction](https://docs.mod.io/restapi/introduction)). `401 / 11005` means the refresh token expired or was revoked ([exchange-oauth-token](https://docs.mod.io/restapi/docs/exchange-oauth-token)).
- `POST /oauth/logout` (`BEARER(read)`) revokes the token; delete it locally afterwards ([logout](https://docs.mod.io/restapi/docs/logout)).
- `GET /me` (`BEARER(read)`) returns the authenticated user ([get-authenticated-user](https://docs.mod.io/restapi/docs/get-authenticated-user)).

### Terms acceptance

- `GET /authenticate/terms` (`KEY`) returns the Terms Object (`plaintext`, `html`, `buttons.agree/disagree`, `links.website/terms/privacy/refund/monetization/manage`), localized by `Accept-Language`. Call it with `X-Modio-Portal` when using platform SSO ([terms](https://docs.mod.io/restapi/docs/terms), [schemas/terms-object](https://docs.mod.io/restapi/docs/schemas/terms-object)).
- "You should prompt players for terms and consent acceptance before using any mod.io functionality." Platform flows take `terms_agreed`, which defaults to `false`. `403 / 11074` means re-prompt. "If the user rejects the Terms of Use, do not attempt authentication." An app that only uses email auth (or none) should "link to the mod.io Terms of Use and Privacy Policy in your Privacy Policy/EULA" ([docs.mod.io/terms](https://docs.mod.io/terms)).
- Agreement text is also available from `GET /agreements/types/{agreement-type-id}/current` (`KEY | BEARER(read)`). Types: 1 Terms, 2 Privacy, 3 Game Terms, **4 API Access Terms ([mod.io/apiterms](https://mod.io/apiterms))**, 5 Monetization, 6 AUP, 7 Cookies, 8 Refund ([get-current-agreement](https://docs.mod.io/restapi/docs/get-current-agreement)).

### What our app needs

```ascii
 first run
   |
   v
 show mod.io Terms + Privacy (GET /authenticate/terms, or the two ?no_links=true URLs)
   |  declined -> browse-only mode (no login)
   v
 login method, in order of preference:
   (1) Sign in with mod.io  -- needs an OAuth app from Ubisoft/mod.io + a tiny token-exchange backend (client_secret)
   (2) Device login (wss)   -- if mod.io confirms third-party use; no secret on disk
   (3) Paste personal token -- works today; fallback and v1 MVP
   |
   v
 store token in OS keychain (Tauri plugin), never in localStorage; on 401 -> clear + re-login
```

## 3. Endpoints needed

### Files and download

| Purpose    | METHOD /path                                         | Auth                | Notes                                                                                                                                          |
| ---------- | ---------------------------------------------------- | ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| List files | `GET /games/{game-id}/mods/{mod-id}/files`           | KEY \| BEARER(read) | Filters: `version`, `virus_status`, `virus_positive`, `filehash`, `date_added` ([get-modfiles](https://docs.mod.io/restapi/docs/get-modfiles)) |
| One file   | `GET /games/{game-id}/mods/{mod-id}/files/{file-id}` | KEY \| BEARER(read) | [get-modfile](https://docs.mod.io/restapi/docs/get-modfile)                                                                                    |

Modfile Object fields we use ([schemas/modfile-object](https://docs.mod.io/restapi/docs/schemas/modfile-object), [schemas/download-object](https://docs.mod.io/restapi/docs/schemas/download-object)):

- `filehash.md5`, `filesize`, `filesize_uncompressed`, `filename`, `version`, `changelog`.
- `download.binary_url` and `download.date_expires`. "If the game requires mod downloads to be initiated via the API, the binary_url ... will contain a verification hash ... and will expire ... Saving and reusing the binary_url won't work."
- `virus_status`: 0 not scanned, 1 scan complete, 2 in progress, 3 too large, 4 not found, 5 error.
- `virus_positive`: 0 no threats, 1 malicious, 2 potentially harmful (e.g. EXEs).
- `platforms[]` of `{platform, status}`, where status is 0 pending, 1 approved, 2 denied, 3 targeted ([schemas/modfile-platform-object](https://docs.mod.io/restapi/docs/schemas/modfile-platform-object)).

**Install rule.** Refuse to install when `virus_positive == 1`. Warn on 2, and on `virus_status` values other than 1.

## 4. Rate limits, caching, pagination, update checks

- **Limits** ([rate-limiting](https://docs.mod.io/restapi/rate-limiting)):
  - Game-linked key: unlimited.
  - User-linked key: 60/min.
  - OAuth user token: 120/min, and 60 writes/min.
  - Per IP: 1000/min, and 60 writes/min.
  - Some endpoints have stricter overrides, which are not listed.
  - The docs mention no `X-RateLimit-*` headers; `retry-after` is the only signal.
- **Prefer the bearer token.** When a request carries both, "the access token takes precedence and the API key is ignored" ([introduction](https://docs.mod.io/restapi/introduction)), so logged-in users run on their own 120/min budget.
- **Caching.** mod.io advises minimizing requests and caching responses, and says it "will discuss usage needs on request" ([introduction](https://docs.mod.io/restapi/introduction)). No ETag or Cache-Control contract is documented; the live 401 probe returned `cache-control: no-cache, private`. Cache in the app (SQLite or a JSON store): tags per game for 24 h, browse pages for 5–10 min, mod detail for 1 h.
- **Pagination.** `_limit` defaults to **100** and `_offset` defaults to 0. Responses carry `result_count`, `result_limit`, `result_offset` and `result_total` ([pagination](https://docs.mod.io/restapi/pagination)). The docs give no maximum above 100; treat 100 as the ceiling.
- **Recommended update check** (one request per 100 installed mods, at app start and every 30–60 min while open):

```ascii
 local DB: {mod_id, installed_modfile_id, md5}
        |
        v
 GET /games/{gid}/mods?id-in=<<=100 ids>&_limit=100      (BEARER(read) if logged in, else KEY)
        |
        +-- mod returned, mod.modfile.id != installed_modfile_id  -> "update available"
        +-- mod returned, same modfile id                          -> up to date
        +-- mod missing from result                                -> GET /mods/{id} directly:
                                                                      404 / status 3 -> "removed from mod.io"
                                                                      visible 0      -> "hidden by author"
 logged in? also GET /me/subscribed?game_id={gid}  -> diff against local installs (new subs from web or in-game)
```

The `id-in` filter is documented in [filtering](https://docs.mod.io/restapi/filtering). The events feed (`GET /games/{gid}/mods/events?id-min=<last>`, [get-mods-events](https://docs.mod.io/restapi/docs/get-mods-events)) is an alternative for very large libraries. `/me/events` is deprecated, so don't use it ([get-user-events](https://docs.mod.io/restapi/docs/get-user-events)).

## 5. API access policy for third-party tools

- **Getting a key.** Game admins get their game's key from the My Content dashboard. "If you are a user working on tools, sites and plugins, you can access an API key for your user account" at [mod.io/me/access](https://mod.io/me/access). Each key comes with its own API path, `u-{user_id}.modapi.io` ([introduction](https://docs.mod.io/restapi/introduction)). The docs describe no review or written-approval step, but the page itself requires a login, which I did not create.
- **Shipping a key in the client.** No docs.mod.io page explicitly allows or forbids it. The docs call the API key "quick and easy to use but limited to read-only GET requests, due to the limited security it offers" ([introduction](https://docs.mod.io/restapi/introduction)). The practical blocker is the shared **60/min** user-key limit ([rate-limiting](https://docs.mod.io/restapi/rate-limiting)). Treat any shipped key as public. **Recommendation:** don't embed one. Options are a tiny proxy holding a key with a negotiated limit, or making browse require login so traffic runs on per-user bearer tokens.
- **Game-owner control.** The game's `api_access_options` bit `OPEN (1)` "Allow 3rd parties to access this games API endpoints" is set by the game admin, which here is Ubisoft ([get-game](https://docs.mod.io/restapi/docs/get-game)). A third-party Anno 117 manager already browses and installs from mod.io (Anno Companion's "Anno 117 Mod Manager", "in no way affiliated with Ubisoft") ([anno-companion.com](https://anno-companion.com/117/?p=2792)). That suggests OPEN is on, but this is inference, not verified.
- **API Access Terms.** They exist as agreement type 4 at [mod.io/apiterms](https://mod.io/apiterms) ([get-current-agreement](https://docs.mod.io/restapi/docs/get-current-agreement)), alongside the [AUP](https://mod.io/aup), [Terms](https://mod.io/terms) and [Game Terms](https://mod.io/gameterms) ([docs.mod.io/terms](https://docs.mod.io/terms)). **I could not read the API Access Terms text:** the page renders client-side and returned only its title to the fetcher. Their wording on key confidentiality, commercial use and attribution is **unverified**. Angelo or a logged-in session should read them before launch.
- **Attribution and branding.** No docs.mod.io page I read requires "Powered by mod.io". The hard requirements I did find:
  - Terms and Privacy must be shown and clickable before auth ([docs.mod.io/terms](https://docs.mod.io/terms)).
  - All displayed content must be reportable ([reports](https://docs.mod.io/restapi/reports)).
  - Any branding rule would sit in the unread API Access Terms.
- **Commercial vs free.** Our app is free, so the marketplace and monetization endpoints don't apply ([monetization](https://docs.mod.io/restapi/monetization)). If a game enables `PAID_DOWNLOADS (8)`, downloads need a bearer token and ownership ([get-game](https://docs.mod.io/restapi/docs/get-game)). Hide paid mods, or link them out to mod.io.
- **Test sandbox.** test.mod.io has separate keys and data, so we can develop without touching production ([introduction](https://docs.mod.io/restapi/introduction)).
